# 1.2.1 (2)

## Fixes

- Both music home and search tab now render a visible TextInput instead of relying on a native header search control.
- Home queries use online song search, including artist keywords; clearing the input restores the recommendation list.
- Pre-cache On/Off translations now match `settings.actions.preloadNextTrack` in both languages.
- App/package/iOS target/share-extension versions are aligned at 1.2.1, build 2.
- Playlist import resolves official QQ and NetEase share short links and text before fetching the playlist.
- Playlist completeness checks continue to reject failed, missing or truncated pages before any local write.
- Source management shows declared channel capabilities and qualities, distinguishing unknown declarations from unsupported actions. The current test exercises QQ (tx), not every channel.
- Optional source `getLyric` exports survive import and reload. Playback prefers source lyrics/translations and supplements missing parts from platform lyrics, guarding stale source/track results.
- Actions names the IPA and artifact from the built app's version/build, for example `CyMusic-1.2.1-build2-unsigned.ipa`.
- Bluetooth lyric mode publishes only the current line, restoring the original song title when disabled or no line is available.
- LRC metadata offset semantics, whitespace-separated timestamp groups and initial highlighting now use the same timing lookup on phone and Bluetooth.

## LiveContainer

The reported device uses LiveContainer. Its guest app entitlements are not applied
to the host, and guest app extensions are not registered. Importing this IPA into
LiveContainer does not by itself grant CarPlay capability or install the share
extension as a system extension. Keep the existing guest data container when
updating to retain songs and preferences. File picker issues can also depend on
LiveContainer's per-app Fix File Picker setting. See the official
[LiveContainer limitations](https://github.com/LiveContainer/LiveContainer#limitations).

Lyric parsing and time selection fixes do not assume a LiveContainer-specific
audio offset. A reported one-line lead still needs a track/source and an observed
playback timestamp to distinguish incorrect LRC timestamps from output latency.

## Verification

### Artwork recovery, export failure and discovery categories

Follow-up device report explicitly showed `[COLLECT]`. The cold-start regression
now leaves Config memory null and invokes the real shareConfigBackup entry point:
before the fix it failed with CONFIG_BACKUP_EXPORT_COLLECT. The app had no startup
call to Config.setup, whereas earlier fixtures had supplied initialized memory.
Export now loads local-config on demand before collecting; confirmed import does
the same before applying preferences. Initialization does not clear collections
or run source scripts. Storage-read failures still produce a safe COLLECT error.

Netease track menus now expose an explicit artwork refresh. It bypasses cached
detail results, uses the original song ID and bounded request queue, and notifies
mounted images. A unique image request suffix forces a reload even when the URL
is unchanged; it is never persisted as artwork metadata. Old image callbacks are
rejected and candidates are only saved after Image.onLoad. Other platforms do
not expose this exact-ID action yet. Native image behavior remains device-only
acceptance, not established by fixture tests.

Regression command: `node scripts/check-config-backup.mjs`. A saved lyric font
index of 1 failed the old 10–80 pixel rule; a real Config.setup fixture reproduced
the export rejection. It now accepts the actual integer range 0–3, normalizes
legitimate legacy outbound songs, isolates damaged outbound rows and retains
strict inbound validation. Export reports safe localized stages and computes
UTF-8 length without requiring TextEncoder. Red evidence was captured at
`/tmp/opencode/config-backup-red.log` (13 pass / 1 fail before the correction).

`check-netease-artwork.mjs` covers first-error exact-ID detail initiation (0ms
under a simulated clock), silent-image recovery at 8 seconds, transient detail
recovery at 5 seconds, newer verified-marker protection, and inactive queue
consumers. These timings measure recovery initiation, not actual image delivery.
Concurrency remains two running / 32 waiting; successful images cancel recovery.

`check-search-discovery.mjs` reproduces the old songs tab displaying Hot playlists
and now checks all four empty-query categories, active-feed gating and synchronous
stale-click protection. Songs only show hot songs, playlists only show popular
playlists, and artists/albums show the query prompt.

These fixes establish fixture behavior, not access to the user's actual device
storage or verification of every remote CDN/native decoder/share-sheet outcome.

### Song information and release records

Both shared track shortcuts and the player options expose Song Information.
The grouped modal reads a bounded opaque-token snapshot; no source resolution,
HEAD request, download or transport command is issued. Actual fallback quality
is shown only with structurally valid resolver provenance. Direct/unknown URLs
do not inherit the globally selected quality. Script names match the complete
source identity (including script SHA256 and platform), so deleted/replaced
scripts cannot be mislabeled as the currently selected source. Format is explicitly
an extension-based inference, not codec validation. Local size uses filesystem
stat with a stale-result guard; remote size remains unknown.

`CHANGELOG.md` records user-facing changes and verification limits by version.
Application update checks use the current fork and compare stable release
versions/builds instead of treating a `v` prefix as a different version.

```sh
node scripts/check-song-information.mjs
node scripts/check-release-version.mjs
```

### Device acceptance: discovery, next-up and configuration transfer

Settings now expose configuration JSON export/import using existing iOS
ActionSheetIOS file sharing and Expo document picking, with no new native
dependency or Pod lock change. Backups include whitelisted MMKV preferences,
portable local-config preferences, source scripts, playlists and favorites.
Preview is side-effect free; only explicit confirmation replaces collections
and synchronizes live stores and both configuration storage systems. Current
queue, progress, local files and credentials are excluded. Imported source
scripts are saved disabled/unselected and never executed by import; users must
review and enable them separately. Export warns that scripts may contain secrets.
Limits are 10 MiB, 200 playlists, 20000 total songs, 100 sources and 512 KiB per
script. Native share cancellation is silent and session export files are cleaned
up after success, cancellation or failure. File export is currently iOS-only.

QQ text search now signs the desktop request after applying query category and
page number. A classified gateway rejection (business code 2000), selected
transport errors or HTTP 5xx allow one fallback; cancellation, malformed data,
unknown business errors and rate limiting do not cause blind repeated requests.
Unsigned gateway rejection was observed in online probes, but the reported
device cold-search failure was not reproduced and may have additional causes.

Empty-query discovery uses QQ's hot-song chart (20 songs) and popularity-sorted
playlist feed (10 playlists), with independent loading/error/retry lifecycles.
Hot-song clicks honor the same saved append mode or default replacement mode,
using a loaded-result snapshot and a separate queue identity. Hidden/stale row
callbacks cannot start playback. The common song shortcut now inserts or moves
the selected platform/id immediately after current playback without restarting
it; prepared next-track data is invalidated when the order changes.

- Cold-launch search: submit a query, change it during a pending request, clear
  it and retry a failed request. Only the latest query may publish results;
  cancellation must not show a search-failed notification.
- With no saved search-mode preference, selecting a search song must create a
  queue from currently loaded results. A deliberately saved alternate mode must
  remain selected after restart.
- Next-up: insert a new song, move an existing queue song, select the current
  song and repeat an insertion. Verify platform-aware deduplication, no current
  playback restart, and the next actual native transition (including shuffle).
- Search discovery: verify real remote ranking/recommendation data, separate
  failure and retry states, playlist navigation, and no discovery results
  replacing an active text search.
- Configuration export/import: cancel the picker/confirmation, reject corrupt
  or oversized JSON and unsupported versions, then restore a valid backup.
  Verify preferences, source declarations and library metadata after the stated
  reload procedure. Device-local audio/cache paths must not be migrated.

These checks need an iPhone/LiveContainer. Linux fixtures and JS export cannot
establish native file-picker/share-sheet behavior or audible next-track handoff.

### Failed playback retries and search queue selection

Failed resolution is no longer installed or persisted as placeholder audio.
Confirmed native failure invalidates the old remote source and headers; native
errors get at most one automatic retry, after which the selected song remains
available for explicit retry. Source loading is bounded to 30 seconds and a
continuous native buffering load has a 45-second deadline. Zero duration alone
does not identify failure: live/unknown-duration or healthy paused items retain
their existing playback behavior. Retired deadlines cannot affect a newer song.

Clicking a failed current list item retries resolution before opening the player;
the player options also expose Resolve Again and Play. Explicit retry always
asks the provider again and may accept a freshly returned stable URL, even if
the same address failed earlier. Automatic retry retains rejection protection.
Remote failure entries are bounded to 128 song identities with 60-second URL
rejection expiry. Known bad local cache files remain separately quarantined.

Search results have a persisted two-mode native menu: append and immediately
play one result in the existing queue, or replace the queue (default) with the
currently loaded song results and start the selected song. Artist/collection
navigation is unaffected. The replacement queue is a snapshot; pagination does
not silently change an already started queue.

Visible NetEase artwork repairs now persist a confirmed URI marker, preserving
working song artwork across refreshes with blank, invalid or unverified remote
image values. Transient busy/negative artwork outcomes have visible/current-only
bounded retries, retaining the existing two-running/32-waiting request limits.
No full-playlist image fetch was introduced.

```sh
node scripts/check-playback-retry.mjs
node scripts/check-search-play-mode.mjs
node scripts/check-netease-artwork.mjs
```

### NetEase song artwork and lyric recovery

Song artwork now merges legacy `album` and modern `al` fields without allowing an
empty modern object to mask a usable legacy cover. Missing or failed images use
same-song CDN/precise image-ID candidates, then fetch details by the original
NetEase ID. Only visible or currently selected songs trigger repair. Detail work
is deduplicated and bounded to two concurrent requests plus 32 queued requests;
confirmed Image.onLoad results are persisted in 250ms batches. Current artwork
is published through metadata-only updates, including confirmations arriving while
the new audio source is still loading. Prepared handoff preserves repaired artwork.

NetEase lyrics support source aliases, business-code validation, primary/legacy
endpoints, bounded retries, same-ID request deduplication and a limited success
cache. Failures are never cached as successful no-lyrics results. Explicit pure
music and uncollected lyrics have separate UI states; transient failure offers a
lyrics-only retry without changing audio, queue or progress. Structured YRC uses
the supplied line start times to produce LRC rather than exposing control fields.
The source-priority lyric path and stale token guards remain in place; switching,
reloading or deleting a source cannot strand a pending lyric UI in loading state.

Checks include 18 artwork repair cases, 12 current-artwork cases, 16 NetEase lyric
helper cases and 25 facade lyric cases, plus existing playback and large-list
regressions. Public IDs 347230 and 186016 returned HTTP 200 image responses;
186016 returned timed lyrics and 5308028 explicitly returned pureMusic. YRC
conversion is validated with protocol-shaped mocks, not an online YRC sample.
Device-specific CDN failures and audio/image rendering still require iPhone checks.

### Bluetooth two-line and three-line displays

With Bluetooth lyrics enabled, system metadata uses the current lyric as title,
`Song - Artist` as artist, and the original album as albumTitle. Intros and gaps
without a current lyric fall back to the original title while retaining the
combined artist field. Disabling or disposing restores all three original fields.
This projection does not mutate saved song data. Empty artist/album values do not
leave a dangling separator or preserve an old album. Updates remain routed through
RNTP so its metadata owner keeps live elapsed/rate information.

`check-carplay.mjs` has 16 passing cases, including full metadata restoration,
same-lyric track changes, missing fields and ignored unadopted native transitions.
Lyric timing (13 cases), RNTP player (36 cases), TypeScript and targeted lint pass.
Actual Bluetooth/CarPlay layout and background behavior still need device checks.

### Playlist and multi-platform follow-up

The reported QQ iOS `n3/other/pages/details/playlist.html` link for playlist
`9791950324` parses correctly. Its API reports 335 ordered slots, but one page
contains 99 detail objects for 100 slots. Pagination now advances using the
reported slot count and verifies the complete ordered numeric ID inventory.
The result contains 334 detail objects plus one clearly unavailable entry
(`1398729200`); unavailable entries never trigger audio lookup or preloading.
The preview discloses the unavailable count. Both the original v8 endpoint and
the newer endpoint expose this detail omission, so changing endpoint alone is
not a fix.

Import/create now share the original two-section layout. Settings and source
management use grouped rows and native action menus; new functions retain the
existing theme and primary color rather than introducing large button cards.

Playback resolution tries `tx` across enabled sources first, then `wy`, `kg`,
`kw`, `mg`. Each platform resolves its own validated music identity rather than
reusing a QQ mid as another platform's ID or hash. Five-platform search schemas
were probed online; plugin URL forwarding and fallback order are covered by
mock/VM regression. Actual five-platform audio decoding and iPhone playback
remain device acceptance work. CommonJS scripts without capabilities retain
the historical tx contract; multi-platform scripts receive `platform` and
`musicInfo` in the optional fifth request context. LX uses its declared source
actions and quality list.

Per-channel diagnostics distinguish declaration, URL-resolution result and
unsupported/unknown channels. Returning a URL is not presented as an audio
playback test. Tests use an isolated script instance and restore the selected
LX runtime. Cache identities include resolution platform; cached fallback
files are checked before network matching. Stuck lyric calls are deadline-bound
and cancelled business requests cannot leave child HTTP requests running.
